## Context

RssReader 是一个 HarmonyOS NEXT (API 12+) RSS 阅读器应用，使用 ArkTS + ArkUI 声明式框架。当前版本已具备完整的订阅、阅读、收藏、搜索、OPML 导入导出功能，但缺乏「记忆」能力。

**当前架构**：
- 页面 → 服务 → 数据库 三层架构
- 服务层均为单例模式
- 数据存储使用 relationalStore (RDB)
- 设置存储使用 preferences

**约束条件**：
- 纯本地存储，无后端依赖
- 个人使用，数据量小
- 需要人类可读、可调试的存储格式

## Goals / Non-Goals

**Goals:**
- 实现三层记忆架构（SOUL / PROFILE / DAILY）
- 自动采集用户阅读行为
- 自动生成和更新用户画像
- 集成通义千问 AI 实现智能排序、简报、精读辅助
- 提供记忆管理界面

**Non-Goals:**
- 云端同步（纯本地）
- 多用户支持（个人专属）
- 复杂 ML 模型（使用外部 AI API）
- 年度报告（P2，后续迭代）

## Decisions

### Decision 1: 使用 Markdown 文件存储记忆数据

**选择**: Markdown 文件存储在 `{context.filesDir}/memory/`

**备选方案**:
- A) 扩展现有 RDB 数据库 - 结构化查询强，但不便于人工查看和编辑
- B) JSON 文件 - 机器友好，但不如 Markdown 可读
- C) Markdown 文件 ✅ - 人类可读、可编辑、易于 AI 理解

**理由**: 作为开发者的个人工具，需要直接查看和编辑记忆内容的能力。Markdown 格式既便于人工调试，也适合作为 AI 上下文输入。

### Decision 2: 行为记录使用防抖批量写入

**选择**: 500ms 防抖 + 内存队列 + 批量追加写入

**备选方案**:
- A) 实时写入 - 简单但 IO 频繁
- B) 固定间隔写入 - 可能丢失数据
- C) 防抖批量写入 ✅ - 平衡性能和实时性

**理由**: 阅读行为可能密集发生（快速浏览），防抖机制既避免频繁 IO，又保证数据不丢失。

### Decision 3: 兴趣权重使用 EMA 算法

**选择**: 指数移动平均（EMA），α = 0.3

**公式**: `newWeight = 0.3 × newSignal + 0.7 × oldWeight`

**备选方案**:
- A) 简单平均 - 历史权重过大
- B) 线性衰减 - 需要存储历史数据
- C) EMA ✅ - 无需存储历史，自然衰减

**理由**: EMA 简单高效，只需存储当前权重，且能自然实现「近期行为更重要」的效果。

### Decision 4: AI 服务使用通义千问 API

**选择**: 通义千问 qwen-turbo 模型

**备选方案**:
- A) 本地模型 - 设备算力限制
- B) OpenAI API - 国内访问受限
- C) 通义千问 ✅ - 国内可用、免费额度、中文优秀

**理由**: 个人使用频率低，免费额度足够；国内直连稳定；中文理解能力强。

### Decision 5: 新增服务类而非扩展现有服务

**选择**: 新增 MemoryService、ProfileService、AIService

**备选方案**:
- A) 扩展 SettingsService - 职责混乱
- B) 新增独立服务类 ✅ - 职责清晰、便于测试

**理由**: 记忆系统是独立功能模块，与现有服务职责不同，应保持单一职责原则。

## Data Flow

### 行为采集流

```
用户行为 → 埋点触发 → 500ms 防抖队列 → 批量写入 daily/*.md
```

### 画像更新流

```
每日首次启动 → 读取 30 天日志 → 聚合计算 → 更新 PROFILE.md
```

### AI 推荐流

```
首页加载 → 获取文章 → 构建上下文(SOUL+PROFILE+今日日志) → AI 打分 → 按分数排序
```

## Risks / Trade-offs

**[Risk] 文件损坏导致数据丢失**
→ Mitigation: 写入前不备份（个人工具，可接受），异常时日志记录

**[Risk] AI 调用失败**
→ Mitigation: 降级为时间排序，缓存上次结果 1 小时

**[Risk] 存储空间占用**
→ Mitigation: 30 天自动清理旧日志，预计占用 ~155KB

**[Risk] AI 响应延迟影响体验**
→ Mitigation: 首页先展示文章，AI 排序在后台异步执行

**[Trade-off] Markdown vs 数据库**
- 优势: 人类可读、易调试、AI 友好
- 劣势: 查询效率低、无事务支持
- 接受: 数据量小，个人使用场景可接受
