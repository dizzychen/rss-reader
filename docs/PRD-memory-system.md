## 一、产品概述

### 1.1 背景

当前 RSS 阅读器已具备完整的订阅、阅读、收藏功能，但缺乏「记忆」能力——每次打开都是全新开始，无法基于历史行为提供个性化体验。

### 1.2 目标

打造一个「越来越懂你」的 RSS 阅读器：

| 目标 | 描述 | 预期效果 |
|------|------|---------|
| **个性化推荐** | 基于阅读历史智能排序文章 | 感兴趣的内容优先展示 |
| **智能简报** | 每日生成符合口味的阅读简报 | 快速了解今日值得读的内容 |
| **精读辅助** | 阅读时提供个性化解读 | 关联知识背景，加深理解 |
| **成长洞察** | 年度阅读报告 | 回顾知识成长轨迹 |

### 1.3 核心理念

参照 OpenClaw 记忆系统架构，采用**三层记忆模型**：

```
┌─────────────────────────────────────────┐
│  SOUL（灵魂层）                          │
│  你的本性：价值观、思维方式、长期目标      │
│  更新频率：季度级                         │
├─────────────────────────────────────────┤
│  PROFILE（画像层）                       │
│  你的近况：兴趣权重、阅读习惯、近期关注    │
│  更新频率：每日                          │
├─────────────────────────────────────────┤
│  DAILY（日志层）                         │
│  你的今天：具体阅读行为、时间、时长        │
│  更新频率：实时                          │
└─────────────────────────────────────────┘
```

### 1.4 设计约束

| 约束 | 说明 | 原因 |
|------|------|------|
| **纯本地存储** | 所有记忆数据存储在设备本地 | 隐私保护，无需联网也能用 |
| **无后端依赖** | 个人专属应用，无需服务器 | 零运维成本 |
| **Markdown 格式** | 人类可读、可编辑、易调试 | 作为开发者可以直接查看和修改 |
| **低资源占用** | 个人使用，数据量小 | 不影响手机性能 |

## 二、功能需求

### 2.1 功能全景

```
记忆系统
│
├── 📝 行为记录（自动）
│   ├── 阅读行为：进入/离开文章、阅读时长
│   ├── 收藏行为：收藏/取消收藏
│   ├── 搜索行为：搜索关键词
│   └── 跳过行为：快速划过的文章
│
├── 🎭 灵魂档案（手动+AI辅助）
│   ├── 身份信息：职业、领域、阶段
│   ├── 思维特质：偏好深度思考、重视实践等
│   ├── 阅读哲学：宁可少读但读透、反感标题党等
│   ├── 长期追求：成为全栈、深入AI等
│   └── 明确不感兴趣：娱乐八卦、股票理财等
│
├── 📊 阅读画像（自动生成）
│   ├── 兴趣权重：AI 0.85、HarmonyOS 0.72 等
│   ├── 阅读习惯：活跃时段、日均阅读、平均时长
│   ├── 近期关注：本周热门主题
│   └── 阅读偏好：偏好长度、类型、来源
│
├── 🤖 AI 功能
│   ├── 智能排序：基于记忆的文章打分排序
│   ├── 每日简报：筛选今日值得读的内容
│   └── 精读辅助：个性化文章解读
│
└── 🛠 维护功能
    ├── 查看记忆：设置页可查看所有记忆文件
    ├── 编辑灵魂：手动编辑 SOUL.md
    ├── 重置画像：手动触发重新生成
    └── 清理日志：自动清理 30 天前日志
```

### 2.2 功能详细说明

#### F1：行为自动记录

**优先级**：P0（核心功能）

**功能描述**：
自动记录用户的阅读行为，为后续的画像生成和 AI 推荐提供数据基础。

**行为类型**：

| 行为 | 触发时机 | 记录数据 | 用途 |
|------|---------|---------|------|
| `READ` | 进入文章详情页 | 文章ID、标题、来源、时间 | 统计阅读量、识别兴趣 |
| `READ_END` | 离开文章详情页 | 阅读时长、滚动深度 | 判断深度阅读 |
| `STAR` | 点击收藏 | 文章ID | 高权重兴趣信号 |
| `UNSTAR` | 取消收藏 | 文章ID | 修正兴趣判断 |
| `SKIP` | 曝光后 1 秒内滑走 | 文章ID | 识别不感兴趣内容 |
| `SEARCH` | 执行搜索 | 搜索关键词 | 识别主动需求 |

**存储格式**：Markdown 表格，每日一个文件

**示例**：
```markdown
# 2026-03-21 阅读日志

## 行为记录

| 时间 | 动作 | 文章ID | 标题 | 来源 | 时长 | 备注 |
|------|------|--------|------|------|------|------|
| 08:15 | READ | 1234 | HarmonyOS NEXT 新特性解析 | 鸿蒙开发者 | 5m | 完读 |
| 08:20 | STAR | 1234 | - | - | - | - |
| 08:32 | READ | 1235 | Claude 4 深度评测 | AI前线 | 8m | 完读 |
```

**交互要求**：
- 完全无感，后台静默记录
- 使用防抖机制，500ms 内的连续行为合并写入
- 仅追加写入，不修改历史记录

#### F2：灵魂档案管理

**优先级**：P0（核心功能）

**功能描述**：
维护用户的「灵魂档案」，描述用户的本质特征，为 AI 提供深度理解。

**档案结构**：

| 字段 | 说明 | 示例 |
|------|------|------|
| 身份 | 职业、领域、阶段 | 软件工程师，移动端开发，正在探索 AI |
| 思维特质 | 认知偏好 | 偏好深度思考，喜欢从原理理解 |
| 阅读哲学 | 阅读习惯和原则 | 宁可少读但读透，反感标题党 |
| 长期追求 | 学习目标 | 成为全栈，深入 AI |
| 明确不感兴趣 | 排除内容 | 娱乐八卦、股票理财 |
| AI 交互偏好 | 与 AI 的沟通风格 | 直接给结论，可用技术术语 |

**入口**：设置页 → 「我的阅读档案」

**交互流程**：

```
┌──────────────────────────────────────┐
│  我的阅读档案                          │
├──────────────────────────────────────┤
│  [预览]                               │
│  职业: 软件工程师                      │
│  领域: 移动端开发                      │
│  思维特质: 偏好深度思考...             │
│  ...                                  │
├──────────────────────────────────────┤
│  [编辑档案]  [AI 帮我完善]             │
└──────────────────────────────────────┘
```

**首次使用**：
- 应用首次启动后第 3 天，弹窗引导填写
- 可跳过，但会影响 AI 推荐效果

**AI 辅助**：
- 累计 30 天行为后，AI 可根据行为推断建议
- 用户确认后写入档案

#### F3：阅读画像自动生成

**优先级**：P0（核心功能）

**功能描述**：
基于最近 30 天的阅读行为，自动生成和更新用户画像。

**画像内容**：

| 维度 | 计算方式 | 示例 |
|------|---------|------|
| 兴趣权重 | 指数移动平均 | AI: 0.85, HarmonyOS: 0.72 |
| 阅读习惯 | 统计聚合 | 活跃时段: 08:00-09:00, 22:00-23:30 |
| 近期关注 | 本周高频主题 | AI Agent, 分布式能力 |
| 阅读偏好 | 行为分析 | 偏好中等长度(1000-3000字) |
| 跳过模式 | 负面信号 | 标题含「震惊」「必看」 |

**兴趣权重算法**：

```
新权重 = α × 新信号 + (1 - α) × 旧权重

其中：
- α = 0.3（衰减因子）
- 新信号 = (本周阅读数 × 1 + 收藏数 × 3) / 总阅读数
```

**更新触发**：
- 每日首次启动 App
- 累计阅读 20 篇后
- 用户手动刷新

#### F4：智能排序

**优先级**：P1

**功能描述**：
首页文章列表按用户兴趣智能排序，而非简单的时间排序。

**排序流程**：

```
1. 获取最新 50 篇未读文章
2. 构建 AI 上下文（SOUL + PROFILE + 今日已读）
3. 调用 AI 为每篇文章打分（1-10）
4. 按分数降序排列
5. 展示排序后的列表
```

**AI Prompt 模板**：

```markdown
你是一个 RSS 阅读助手。请为以下文章打分（1-10）。

## 用户灵魂
{SOUL.md 内容}

## 用户画像
{PROFILE.md 内容}

## 今日已读
{今日日志摘要}

## 待排序文章
1. [ID:1234] 《HarmonyOS NEXT 新特性》 - 鸿蒙开发者
2. [ID:1235] 《震惊！这个技巧...》 - 营销号
...

## 输出格式
返回 JSON: {"scores": {"1234": 9, "1235": 2}, "reason": "简要理由"}
```

**降级策略**：
- AI 调用失败时，按时间排序
- 缓存上次排序结果 1 小时

**UI 交互**：
- 首页右上角显示排序方式：「智能」/「最新」
- 点击可切换

## 三、非功能需求

### 3.1 性能要求

| 指标 | 要求 | 说明 |
|------|------|------|
| 行为记录延迟 | < 100ms | 不影响阅读体验 |
| 画像更新时间 | < 3s | 启动时后台更新 |
| AI 排序响应 | < 5s | 首页加载完成后异步执行 |
| 日志文件大小 | < 10KB/天 | 30 天约 300KB |

### 3.2 存储要求

| 项目 | 估算 | 说明 |
|------|------|------|
| SOUL.md | ~2KB | 固定大小 |
| PROFILE.md | ~3KB | 固定大小 |
| 每日日志 | ~5KB | 按阅读量浮动 |
| 30 天总计 | ~155KB | 自动清理旧日志 |

### 3.3 隐私要求

| 要求 | 实现方式 |
|------|---------|
| 数据本地存储 | 存储在 `context.filesDir/memory/` |
| 不上传云端 | 无后端、无网络存储 |
| 用户可删除 | 设置页提供清除入口 |
| 用户可导出 | 设置页提供导出入口 |

## 四、数据流设计

### 4.1 行为采集流

```
用户行为
    │
    ▼
┌─────────────┐    500ms 防抖    ┌─────────────┐
│ 埋点触发     │ ────────────────► │ 批量写入     │
│ (页面/组件)  │                  │ (daily/*.md) │
└─────────────┘                  └─────────────┘
```

### 4.2 画像更新流

```
每日首次启动
    │
    ▼
┌─────────────┐    聚合计算     ┌─────────────┐
│ 读取 30 天   │ ────────────────► │ 更新        │
│ 日志文件     │                  │ PROFILE.md  │
└─────────────┘                  └─────────────┘
```

### 4.3 AI 推荐流

```
首页加载
    │
    ▼
┌─────────────┐  构建上下文  ┌─────────────┐  调用API  ┌─────────────┐
│ 获取文章列表 │ ───────────► │ SOUL +      │ ────────► │ AI 打分     │
│ (50篇)      │             │ PROFILE +   │          │ (通义千问)  │
└─────────────┘             │ 今日日志    │          └─────────────┘
                            └─────────────┘                │
                                                          ▼
                                                   ┌─────────────┐
                                                   │ 按分数排序   │
                                                   │ 展示列表     │
                                                   └─────────────┘
```

## 五、实现计划

### 5.1 里程碑

| Phase | 内容 | 工期 | 产出 |
|-------|------|------|------|
| **Phase 1** | 基础设施 | 3 天 | MemoryService、文件操作、数据模型 |
| **Phase 2** | 行为采集 | 3 天 | 埋点、防抖、日志格式化 |
| **Phase 3** | 灵魂档案 | 2 天 | SOUL 编辑页、引导流程 |
| **Phase 4** | 画像更新 | 3 天 | 聚合算法、自动更新、日志清理 |
| **Phase 5** | AI 集成 | 5 天 | AIService、智能排序、简报、解读 |

**总工期**：约 16 天（2-3 周）

### 5.2 验收标准

| Phase | 验收标准 |
|-------|---------|
| Phase 1 | 能正确读写 SOUL.md、PROFILE.md、daily/*.md |
| Phase 2 | 阅读行为自动记录到日志，查看日志内容正确 |
| Phase 3 | 能在设置页查看和编辑灵魂档案 |
| Phase 4 | 每日启动自动更新画像，30 天前日志自动清理 |
| Phase 5 | 首页按兴趣排序，能生成每日简报和精读解读 |

## 六、风险与应对

| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|---------|
| 文件损坏 | 低 | 高 | 写入前备份，异常时回滚 |

| 性能问题 | 中 | 中 | 防抖批量写入，异步加载 |
